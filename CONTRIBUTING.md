# Contributing to EchoPaw

EchoPaw is in planning. Start with the [README](README.md) and the focused documents in `docs/`. Planning fixes, source verification, user-flow feedback and tightly scoped prototypes are welcome. Discuss architecture changes or production work in an issue before opening a large pull request.

1. Ask or file an issue describing the user problem, suggested change and how to verify it. Use the [private reporting path](SECURITY.md) for security findings.
2. Make one focused change. Keep decisions, proposed behavior and test results distinct. For provider and platform claims, link primary documentation, add the date reviewed, and record what needs a live or hardware check.
3. Keep credentials, viewer content, personal mascot material, and voice files out of commits, examples and screenshots. Use synthetic test data and assets you have permission to contribute. Include relevant license and author details for new dependencies or assets.
4. Run the applicable build or test instructions in the owning directory. For text-only changes, check links, paths and `git diff --check`. List results and manual checks still pending in your pull request.

For the documentation site, follow [the site’s local build instructions](apps/docs/README.md). Native and plugin build instructions will accompany their first buildable projects. Contributions are covered by [the repository license](LICENSE) unless a file has its own stated license and permission.

Follow the [Code of Conduct](CODE_OF_CONDUCT.md) in project spaces.
