# Microphone reactions and wake phrases

Research checked 2026-11-18. Voice activity and wake-phrase listening are independent opt-ins. Both start off. A shared **Stop listening** command closes capture, drops pending recognition and clears both enabled states. Opening settings, connecting Twitch and running the safe preview never request microphone access.

| Feature | Reads | Produces | Sends |
| --- | --- | --- | --- |
| Voice activity | Short windows of selected microphone samples | A local state such as attentive, then idle | Nothing to the cloud |
| Wake phrase | Selected microphone samples during an explicitly enabled local recognition session | One keyword event after a valid match | The event can initiate a normal, PackGuard-checked OpenAI text interaction. Audio and transcripts stay local in this mode. |
| Push-to-talk | Mic samples during a bounded, deliberate turn after initial consent | A wake or ask event, with local transcript only when the user explicitly chooses a voice question | For a voice question, show that recognized text may be sent to OpenAI with the request. |
| Cloud transcription, later | A deliberately captured short clip | Recognized text for one turn | Audio leaves the Mac only in this separately disclosed, explicit opt-in mode. |

## Capture, permissions and stop behavior

Use one input path and one input device for both features. Expose System Default and a Core Audio input UID picker. First prototype a dedicated `AVCaptureSession` with an explicit audio device and bounded sample delivery. Confirm that it lists and binds the intended physical inputs, including an external interface. If device behavior or waveform processing needs a lower-level pipeline, compare a dedicated `AVAudioEngine` input tap and the documented HAL input Audio Unit. Keep simultaneous playback independent from the selected mic unless tests justify a shared echo-cancelling graph. [Apple capture sessions](https://developer.apple.com/documentation/avfoundation/setting-up-a-capture-session), [Apple AVAudioEngine](https://developer.apple.com/documentation/avfaudio/avaudioengine), [Apple HAL input](https://developer.apple.com/library/archive/technotes/tn2091/).

Request macOS microphone access only after the user chooses a mic feature or PTT. Use `NSMicrophoneUsageDescription` and confirm the hardened-runtime Audio Input entitlement on the signed build. The Apple Speech framework has its own `NSSpeechRecognitionUsageDescription` and authorization flow, including local-only use. Request it only for recognition. Denied or revoked permission leaves the corresponding feature off and gives a System Settings path and manual trigger. If a selected input disappears or playback/reconfiguration invalidates a turn, discard in-flight buffers and ask the user to resume after reconnect. No silent substitution of a loopback or another microphone. On sleep, quit or emergency stop, transition to off and release capture. [Apple macOS capture authorization](https://developer.apple.com/documentation/bundleresources/requesting-authorization-for-media-capture-on-macos), [Audio Input entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.device.audio-input), [Speech permissions](https://developer.apple.com/documentation/speech/asking-permission-to-use-speech-recognition).

Keep samples only in bounded volatile buffers. Discard partial text as the turn ends. Store neither recordings nor raw transcripts by default. Diagnostics may report counts and reasons such as permission denied or cancelled without attaching audio or transcriptions. Validate zero outgoing audio during voice activity and local wake testing using traffic inspection and offline operation.

## A. Voice activity reactions

Start with a level heuristic for animated attentiveness. Compute RMS on 20 ms mono frames. Calibrate noise level during a brief user-triggered, local test. Use hysteresis and time gates rather than classifying one frame. Initial tuning candidates are ~120 ms to enter and ~400 ms to release, with a configurable sensitivity. Instrument quiet rooms, fans, gameplay bleed and keyboard noise. Label false positives and tune the detector before describing it as speech recognition. Compare lightweight local VAD if a level heuristic fails the acceptance test.

Emit only transitions, never a conversation request. Pick an authored attentive pose when available and a small whole-sprite motion if the pack supports no attentive pose. With Reduce Motion enabled, use a static expression or status. Update the visible level meter independently at a modest rate. Never send either microphone samples or detected activity to a provider for this feature.

## B. Wake phrase and push-to-talk

1. Use a configurable phrase and locale, with a longer phrase suggested when short words false-trigger. Normalize token boundaries and locale-sensitive casing, match a complete phrase and deduplicate repeated recognition updates within a single utterance. Use initial 500 ms debounce, 15 s wake cooldown and the scheduler's global caps. Approve at most one response for a matched turn.
2. On macOS 15 evaluate `SFSpeechRecognizer` only when `supportsOnDeviceRecognition` is true. Require `requiresOnDeviceRecognition = true` and handle failure with recognition off. Apple documents availability, throttling and task duration considerations, so prove segmentation, restarting after errors and continuous use before shipping an always-listening switch. For supported newer OS versions, compare on-device `SpeechAnalyzer` / `SpeechTranscriber` with locale and asset availability checks. Its model assets may require download. [SFSpeechRecognizer limits](https://developer.apple.com/documentation/speech/sfspeechrecognizer), [Local recognition guarantee and precondition](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/requiresondevicerecognition), [SpeechTranscriber availability](https://developer.apple.com/documentation/speech/speechtranscriber), [Apple WWDC on-device transcription](https://developer.apple.com/videos/play/wwdc2025/277/).
3. Evaluate Sound Analysis with a small trained classifier if always-on transcription uses too much CPU or misses timing targets. A trained closed vocabulary needs representative negative examples and cannot recognize arbitrary phrases without new training or another model. Preserve arbitrary phrase support through the verified local recognition path and use manual/PTT controls when that path is unavailable. [Apple Sound Analysis](https://developer.apple.com/documentation/soundanalysis).
4. PTT starts on a deliberate press and stops on release or after 8 seconds. Provide keyboard and click-to-start/click-to-stop equivalents with the same timeout. A plain manual reaction remains available without microphone access. If local recognition fails, keep manual controls and the local visual activity feature available. Any future cloud transcription should be PTT only initially, with provider, destination, retention link and per-turn preview visible. [OpenAI speech-to-text](https://developers.openai.com/api/docs/guides/speech-to-text).

Suppress local detection from before playback begins until the output drains plus a 400 ms candidate tail. Keep the active suppression state visible. For an explicitly deliberate barge-in PTT, stop speech first and wait for drain before opening the turn. Reject selecting the same virtual loopback for capture and speech output. Headphones are the dependable isolation step. Test Apple voice processing as an optional improvement on validated routes. Device and graph behavior vary, and software gating cannot prevent all acoustic or external OBS feedback. [Apple AVAudioIONode voice processing](https://developer.apple.com/documentation/avfaudio/avaudioionode/setvoiceprocessingenabled(_:)).

## Controls and test gates

Show **Microphone off**, **Listening locally**, **Push-to-talk active**, **Temporarily paused during speech**, or **Permission needed** with text and an icon in the menu bar and Dashboard. Provide independent toggles, **Stop listening** in one action, the input picker, a phrase test, and a keyboard shortcut with visible focus. Announce state changes to VoiceOver, leave the meter quiet, and offer numeric sensitivity and timing controls.

- [ ] Test permission denial, revocation, no device, hotplug, sleep and cancellation while recognition emits a partial result.
- [ ] On macOS 15 with Internet disabled, test a supported and unsupported locale. Confirm no fallback uploads and see a manual alternative when recognition is unavailable.
- [ ] Proposed gate for voice activity is p95 onset ≤250 ms with a calibrated headset. Proposed one-hour false wake gate is ≤1 false activation in a representative negative stream and zero self-wakes in 100 approved TTS repetitions across wired monitoring and speaker bleed.
- [ ] Use at least 30 chosen-phrase trials across intended voices/noise per supported locale. Proposed p95 wake decision ≤1 s after the phrase ends and recall ≥90% for the tested cohort. Record setup and errors before setting a support claim.

Review these figures against shipping hardware. No microphone, keyword or accessibility behavior has been benchmarked.
